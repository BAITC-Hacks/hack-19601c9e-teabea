# Финальный комплект для вашей команды

Здесь уже лежит проект Клауда с данными. Код сохранён без исправлений: задания ниже предназначены для ваших ИИ в VS Code. Старые выгрузки в out/ — проверенный исходный результат, но в классификации есть ошибки. Нельзя сдавать их без доработки и повторного расчёта.

## Что делать прямо сейчас

1. Распакуйте комплект и откройте папку money-graph-final-kit в VS Code.
2. Бэкендер отправляет своему ИИ: «Прочитай 01_BACKEND.md и 04_CONTRACT.md, выполни задание полностью в этом проекте. Создай код, запусти проверки и пересчитай данные».
3. Фронтендер отправляет своему ИИ: «Прочитай 02_FRONTEND.md и 04_CONTRACT.md, выполни задание полностью в этом проекте. Сделай рабочий интерфейс на имеющемся Streamlit».
4. После объединения изменений отправьте одному ИИ: «Выполни 03_FINISH.md. Проверь настоящий сквозной запуск, подготовь README и демо».

Полные тексты промптов находятся в соответствующих файлах. Если ИИ не читает файлы проекта, скопируйте содержимое промпта и 04_CONTRACT.md в чат.

Работайте в отдельных ветках/копиях либо разделите файлы. Бэкендер меняет pipeline.py, requirements-core.txt, scripts/ и tests/test_pipeline.py. Фронтендер меняет app.py, requirements-ui.txt, ui/ и tests/test_ui.py. Корневые requirements.txt, README.md и run.py объединяет ответственный за интеграцию. DATA, pqmini и исходный HTML без необходимости не менять.

## Решение по архитектуре

Сохраняем существующий Python-пайплайн и Streamlit + PyVis. Обмен между ними — рассчитанные CSV; отдельный REST API не требуется. Это заменяет предыдущие промпты на React/FastAPI: не запускайте обе архитектуры одновременно.

Обязательный продукт: из трёх parquet получить три CSV и экран, где аналитик находит любой gid, видит направленные связи, предполагаемую роль, ограничения и численные причины приоритета. Главное — защита правил перед жюри. Чат-бот, авторизация, облако, БД и ML-обучение в MVP не нужны.

## Что есть и что предстоит

- Есть оригинальный код, 3 parquet, конвертированные CSV, исходные результаты, HTML-просмотрщик, ТЗ, проверка CSV и точные задания.
- Предстоит исправить классификацию и UI, добавить единый запуск от parquet, установить зависимости, выполнить реальные тесты приложения.
- README.md пока оригинальный и содержит неточности. На этапе разработки ориентируйтесь на 04_CONTRACT.md и AUDIT.md; финальный README нужно переписать по фактическому результату.
- Для запуска собственного парсера сейчас нужен конкретный Linux-путь к libzstd; основной Windows-сценарий должен читать parquet через pyarrow.

## Целевые команды после выполнения промптов

Это контракт для создаваемого кода, не утверждение, что команда run.py уже существует.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe pipeline.py --data data_parquet --out out
.\.venv\Scripts\python.exe run.py
```

run.py должен выполнить пересчёт и затем запустить интерфейс. Повторный запуск экрана без пересчёта:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py -- --data out --edges data/edges.csv
```

Бэкендер обеспечивает обновление совместимого data/edges.csv из исходного parquet. В дальнейшем относительные пути вычислять от корня проекта, а не случайного рабочего каталога. После успешной установки запуск демо не требует внешней сети.

## Распределение времени

- Первые 15 минут: оба участника читают контракт и аудит.
- Следующие 75–90 минут: бэкенд исправляет расчёт и чтение parquet; фронт — действия, идентификаторы и автономность.
- Следующий час: таблицы, карточки, скачивания, численные объяснения; соединение частей.
- Затем 45 минут: чистый сквозной прогон и исправления.
- Остаток: README, диаграмма и репетиция пяти минут демо.
