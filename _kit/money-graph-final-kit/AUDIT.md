# Что проверено в исходном архиве

Проверка выполнена по содержимому graf_deneg.zip и ранее переданного HTML. Численные результаты сохранены в audit_original.json. Исходный код в этом комплекте не исправлен.

## Подтверждено

- 2248 уникальных узлов, 3119 рёбер, 4840 транзакций; 2248 результатов ролей, 89 кластеров, топ-40.
- Набор gid в nodes_roles.csv точно совпадает с data/nodes.csv.
- Пары транзакций совпадают с edges.csv; суммы совпадают с допуском 0.01 KZT и rel_tol=1e-12; количество транзакций по каждой паре совпадает точно.
- Концы рёбер есть в nodes.csv. Scores конечны и лежат в 0–1. Максимальная длина evidence — 106 символов. Топ отсортирован по приоритету.
- Сумма размеров кластеров — 2248. Каждый исходный parquet побайтово совпадает с соответствующим файлом из data (1).zip пользователя.
- Распределение: terminal 1092, peripheral 964, coordinator 78, transit 65, consolidator 29, distributor 20.

Это проверка внутренней согласованности готовых CSV. Она не подтверждает корректность собственного декодера parquet или научную обоснованность ролей.

## Исправить до сдачи

1. pipeline.assign_role относит ВСЕ 19 изолятов к terminal: условие out_deg==0 не требует положительного входа. Всего среди terminal 30 seed. Изоляты должны быть peripheral с явным недостатком данных; terminal — осторожная гипотеза при наблюдаемом входе, без границы и без seed.
2. Координатор назначается уже по двум соседям-seed через OR. Двенадцать coordinator имеют нулевую betweenness. Это не само по себе доказательство ошибки метрики, но двух соседей недостаточно для утверждения об организаторе. Нужны несколько структурных сигналов и осторожная формулировка.
3. Ветка frontier-consolidator в terminal-части недостижима: раньше срабатывает общий consolidator при том же входящем пороге и out_deg=0. Если в другом датасете frontier имеет большой входящий веер, он получит объяснение «отдаёт 0%» без ограничения наблюдения. Исправить общее правило и его evidence.
4. Уточнение предыдущего обзора HTML: исходный алгоритм НЕ запрещает консолидацию на четвёртом колене. В текущем результате таких узлов нет; нужно сохранить эту возможность, исправив объяснение.
5. Метрики изолятов восстанавливаются после графа. Лучше добавить все nodes до метрик и сохранить все nodes при создании проекции. На графе без рёбер нужен отдельный безопасный путь кластеризации.
6. sanity_check сравнивает пары и суммы, но НЕ n_tx, хотя агрегированное количество уже рассчитано. Добавить проверки схемы, дубликатов, ссылок и числа переводов. np.allclose по умолчанию слишком свободен для больших сумм; задать допуск явно.
7. load() читает только CSV. README ошибочно называет скрипт независимым от формата. Основной запуск от parquet одной командой отсутствует.
8. requirements.txt не содержит scipy, нужного используемым реализациям PageRank/HITS. Комментарии внутри requirements не делают зависимости опциональными. Состав зависимостей нужно разделить и проверить на чистом окружении.
9. pqmini/zstd_ctypes.py загружает жёстко заданный /usr/lib/x86_64-linux-gnu/libzstd.so.1. Это Linux-зависимость, на Windows такой основной путь непригоден. Совпадение CSV с результатом стандартного reader здесь не проверялось.
10. app.py записывает /tmp/_graph.html: непереносимый путь, общий для сессий. Встраивать сгенерированный HTML из памяти, без этого временного файла.
11. Кнопка «Показать на графе» пишет st.session_state['_focus'], но этот ключ нигде не читается. Кнопка полного графа действует один rerun, после следующего взаимодействия режим теряется. Состояние хранить явно.
12. Пустой список ролей показывает все роли из-за условного выражения. Исправить на пустой результат или отдельное ясно названное действие «Сбросить».
13. PyVis и HTML получают gid числом. Все 2248 gid превышают Number.MAX_SAFE_INTEGER. Нужны строки на границе визуализации; не переводить int64 через float.
14. viewer_original.html загружает vis-network с CDN; это не автономный HTML. app.py тоже требует проверки ресурсов создаваемого PyVis HTML. Не заявлять offline без проверки браузера.
15. HTML каждый раз создаёт Network без destroy; в Streamlit таблица топа не выбирает узел по клику без исправления состояния. Нет кнопок выгрузки CSV.
16. «Настоящий terminal», «деньги не задерживаются», «явный организатор», «курьеры» — чрезмерные выводы. Данные показывают только часть переводов, без разметки ролей и доказательства движения тех же денег.
17. README путает количество контрагентов с суммой денег: условия in_deg>out_deg не означают in_kzt>out_kzt. Все описания привести в соответствие с кодом.
18. Betweenness по 1/sum_kzt — выбранная модель стоимости пути, НЕ измеренная вероятность маршрута. Для MVP проще невзвешенное направленное посредничество; при сохранении обратного веса явно обозначить допущение.

## Что не проверено запуском

В текущем окружении нет networkx и pyarrow, поэтому здесь не повторялся пайплайн, не запускались конвертер и Streamlit. Не подтверждены время «меньше 5 секунд», запуск на чистой машине, совпадение собственного парсера со стандартным reader и работа UI в браузере. Всё это включено в задания ниже.
