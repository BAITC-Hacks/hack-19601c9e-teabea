# Промпт для финальной интеграции и сдачи

Доведи существующий проект «Граф денег» до сдачи. Прочитай 04_CONTRACT.md и AUDIT.md, проверь изменения бэкенда и фронтенда. Если соответствующие исправления ещё не сделаны, сначала выполни нужные части 01_BACKEND.md/02_FRONTEND.md. Не объявляй приложение готовым по наличию исходных CSV.

1. Объедини requirements-core.txt и requirements-ui.txt через корневой requirements.txt. Создай чистое виртуальное окружение, установи зависимости и запиши реально проверенные версии Python/пакетов. Установка может использовать сеть; дальнейшее демо — локальное.
2. Запусти реальные unit-проверки и CLI от data_parquet, не от ранее приготовленных CSV. Временные результаты держи в отдельном каталоге. Сверь схему, полный набор узлов, scores, evidence, кластерное покрытие, минимум 20 в топе. Сверь все три parquet со стандартным reader; не заявляй проверку собственного парсера, если не выполнял её.
3. Добавь run.py. Он запускает pipeline через sys.executable, передаёт абсолютные пути, ждёт успешного выхода, затем запускает `sys.executable -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501 -- --data <out> --edges <data/edges.csv>`. При ошибке расчёта UI не стартует. Корректная остановка Ctrl+C без оставленного дочернего сервера. Одна команда `python run.py` после установки обеспечивает пересчёт и интерфейс. Не поднимай отдельные API и Node-серверы.
4. В браузере проверь поиск произвольного gid, выбранный узел из топа, изолят, boundary, фильтры, полную сеть, кластеры, скачивания и отсутствие CDN-зависимости. Запросы интерфейса к самому localhost допустимы, внешние ресурсы для работы не нужны. Streamlit telemetry можно выключить локальной конфигурацией. Не заявляй визуальную проверку по py_compile.
5. Повтори расчёт и сравни три обязательных CSV на воспроизводимость. Время полного расчёта parquet→выгрузки должно быть ≤300 секунд на фактической машине, без учёта установки пакетов. Не обещай «<5 секунд» без замера. Номер кластера и порядок равных приоритетов стабильны.
6. Перепиши README: назначение, установка на Windows с .venv без обязательной активации PowerShell, команды CLI и run.py, выводимые файлы, критерии шести ролей, формулы score/priority, пересечения ролей, ограничения и фактическое распределение. Удали старые неподтверждённые утверждения о «настоящих terminal» и формате input. Сохрани отдельный раздел pqmini как ограниченный Linux fallback, если оставлен в репозитории.
7. Масштабирование до 1 млн: NetworkX заменить компактным/компилируемым представлением графа, центральность приблизительная, колоночная обработка, выдача только выбранных подграфов, пакетная кластеризация. Не обещать, что глобальные PageRank/betweenness пересчитываются точно только у ближайших соседей без влияния на остальной граф.
8. Создай docs/architecture.md с диаграммой parquet → валидация → направленный граф и признаки → Louvain/роли → приоритет и объяснения → CSV → Streamlit/PyVis. Сохрани диаграмму в доступном формате для одного слайда, если инструменты позволяют; минимально Mermaid в README.
9. Создай docs/demo.md с 5-минутным сценарием: 0:00 проблема; 0:30 настоящий запуск и длительность; 1:15 топ и первый узел; 2:15 другой тип роли; 3:00 поиск произвольного gid; 3:40 boundary и ограничения; 4:20 три CSV, схема и масштабирование. Узлы для примеров выбери из текущего результата программно. Их можно записать в сценарий, но не зашивать в классификатор.
10. Подготовь архив сдачи без .venv, __pycache__, .git, логов с личными путями и старых ошибочных out. Добавь исправленные результаты. Данные включай только для предусмотренной организаторами передачи в рамках хакатона, не публикуй наружу.

В финале укажи точный путь архива, команду установки, одну команду запуска, локальный URL, фактическое время расчёта, результаты тестов и оставшиеся ограничения. Если что-то не удалось проверить, отметь это отдельно, не заменяй проверку обещанием.
