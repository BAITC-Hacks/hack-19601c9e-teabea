# Проверки интеграции

Результаты двух реальных CLI-прогонов от `data_parquet` находятся в [verification.json](verification.json).
Полное время измерено вокруг дочернего процесса: включает запуск Python и публикацию CSV.
Внутреннее `pipeline_seconds` из metadata заканчивается до публикации и потому меньше полного времени.

Проверено на чистом `.venv-ui`: Python 3.12.10, Windows x64. Полный список установленных пакетов — [tested-environment.txt](tested-environment.txt).
Streamlit 1.55 несовместим с pandas 3; используется Streamlit 1.64.0 и PyVis 0.3.2.

Повторение проверки:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
.venv\Scripts\python.exe scripts/verify_release.py
.venv\Scripts\python.exe -m pytest tests/test_pipeline.py tests/test_ui.py tests/test_run.py -q -p no:cacheprovider
```

Проверяются три parquet стандартным pyarrow, ссылки и агрегаты через неизменённый pipeline, покрытие всех узлов, scores, evidence, кластеры, глобальный топ, сумма вкладов приоритета и побайтная воспроизводимость трёх CSV. Собственный pqmini не запускается и не сравнивался.

UI-проверки: строковые gid в сериализованном PyVis, отсутствие внешних script/link, изолят, соседство в обе стороны на 1–2 шага, пустой фильтр, проверка схемы и обновление fingerprint. Streamlit AppTest проверяет поиск, неизвестный gid, топ, сохранение режима всей сети, сброс, кластер, boundary, обновление данных и наличие трёх загрузок. Тесты run.py проверяют порядок запуска, абсолютные пути, остановку ребёнка и отказ от UI при ошибке расчёта.

Первый полный прогон: **13 passed in 26.29s**. `run.py` успешно пересчитал стандартный out и запустил Streamlit на 127.0.0.1:8501. HTTP GET `/_stcore/health` вернул 200 и `ok`.

После добавления проверки реального содержимого загрузок и изменения результатов: **5 UI tests passed in 25.00s**. В сумме подтверждены 14 тестов (6 pipeline + 5 UI + 3 launcher). Байты всех трёх download_button совпадают с полными CSV даже после фильтрации. Обновлённое explanation появляется после обновления; удаление обязательного поля останавливает экран с инструкцией пересчёта.

Реальная проверка `scripts/check_launcher.py` на Windows: пересчёт, HTTP 200 на временном порту 8502, console CTRL_BREAK_EVENT, завершение launcher с кодом 0 и отсутствие слушающего сервера после остановки — PASS. Короткие ожидания в run.py позволяют Python обрабатывать сигналы Windows; дочерний процесс получает сигнал своей группе, при превышении таймаута останавливается дерево. Финальные launcher-тесты: 3 passed in 0.11s. Клавиатурное нажатие Ctrl+C через интерактивный терминал отдельно не автоматизировалось; SIGINT обрабатывается тем же путём KeyboardInterrupt.

Браузерный инструмент не обнаружил доступных браузеров; попытка открыть Chrome вернула `Browser is not available: chrome`. Визуальный вид при 1280×720, клики по canvas, фактическое скачивание в браузере и работа при блокировке внешней сети не подтверждены. Статическая проверка HTML доказывает отсутствие внешних script/link, но не заменяет эти проверки.

Особенность окружения: исходная `.venv` ссылается на недоступный Python 3.13; создана отдельная `.venv-ui`. При повторении здесь используйте `.venv-ui\Scripts\python.exe`. В новой распакованной поставке создайте `.venv` по README.
